# Развёртывание с доступом через интернет

Нужны Linux-сервер с Docker Compose, домен с DNS-записью на сервер и открытые
TCP-порты 80/443. SSH ограничьте доверенными адресами. Порты 8000 и 5173 наружу
не публикуются. Сборку контейнера и выпуск сертификата необходимо проверить на
целевом сервере: локально Docker daemon не был доступен.

1. Скопируйте исходники проекта без `.env`, `.secrets`, `tmp` и пользовательских данных.
2. Скопируйте `deploy/.env.example` в `.env.production` в корне проекта.
3. Укажите реальный `DOMAIN` без протокола и новый `LLM_API_KEY`. Перед публикацией
   замените ключ, который был отправлен в чат. Настройте лимит расходов у провайдера.
4. На машине с установленным backend выполните `python -m cqa.admin --env-file .env.production`.
   Введите отдельный пароль сервера. Передавайте env-файл по защищённому каналу,
   на сервере ограничьте права: `chmod 600 .env.production`.
5. Из корня проекта выполните:

```sh
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production up -d --build
```

Не запускайте `config` без `--quiet` при записи терминала: полный вывод содержит
подставленные секреты. Caddy получает TLS-сертификат автоматически. Войдите через
`https://ваш-домен`. HTTP должен перенаправлять на HTTPS; `/healthz` возвращает
только состояние, а `/api/conversations` без входа — 401.

Compose создаёт новое пустое хранилище. DEV можно импортировать через интерфейс.
Не добавляйте исходные аудио, базу и ключи в Docker image: `.dockerignore` пропускает
только необходимые файлы сборки. Данные хранятся в volume `cqa_data`.

Backend доверяет proxy-заголовкам внутри выделенной сети Compose, где работают
только app и Caddy. Не публикуйте порт app и не подключайте к сети недоверенные
контейнеры. При другой топологии ограничьте `--forwarded-allow-ips` адресом прокси.

После изменения секретов выполните
`docker compose --env-file .env.production up -d --force-recreate app`.
Для смены пароля повторите команду `cqa.admin`; старые сессии будут недействительны.
В настройках модели сначала проверьте доступность модели у вашего провайдера.

Регулярно сохраняйте резервную копию volume при остановленном app либо через
SQLite backup API. Проверяйте восстановление. Шифрование диска, доступ к резервным
копиям и срок хранения диалогов настраиваются владельцем сервера. Не выполняйте
`docker compose down -v`, если данные нужно сохранить.
